# Назначение отсутствующего XML-ключа через исходный XLSX Prom

Дата: 20.10.2026, Europe/Kyiv. Проверена существующая тестовая карточка
`3240302692`, артикул `test`, исходный статус `not_on_display`, API `external_id=null`.

Результат: ключ `dnk-xlsx-probe-3240302692` назначен **тому же native ID**.
Новых и пропавших native ID нет: до/после — 27 карточек. Значения всех API-полей
остальных 26 карточек совпали. У тестовой карточки импорт изменил `external_id`,
`date_modified` и **видимость** (`not_on_display → on_display`). Исходная видимость
восстановлена отдельным `POST /products/edit` только с `id` и `status`; повторное
чтение подтвердило `not_on_display`. После восстановления у исходной карточки
отличаются только `external_id` и технический `date_modified`.

## Исходные файлы

- [source-single-product.xlsx](source-single-product.xlsx) — настоящий экспорт
  выбранной скрытой карточки из кабинета Prom, формат XLSX, украинские заголовки,
  видимость экспорта «Все позиции». Результат экспорта появляется в уведомлениях;
  подготовка заняла несколько минут.
- [12-assign-xml-key.xlsx](12-assign-xml-key.xlsx) — копия экспорта. Изменено только
  значение `Export Products Sheet!Z2` (`Ідентифікатор_товару`): `null → ключ`.
  `Y2` (`Унікальний_ідентифікатор=3240302692`), все остальные ячейки и оба листа
  сохранены. После экспорта файла выполнено независимое сравнение всех значений.
- [results.json](results.json) — обезличенный протокол, хеши файлов и результат.
  Credentials, cookies и полные API-снимки в репозиторий не включены.

## Проверенная последовательность

1. Получить свежий собственный XLSX-экспорт нужной карточки и сохранить оригинал.
2. Найти существующий native ID в `Унікальний_ідентифікатор`, не менять его.
   Задать уникальный постоянный строковый `Ідентифікатор_товару`, сохранив прочие
   значения и служебные столбцы.
3. Загрузить файл с компьютера в кабинете Prom. В данном тесте:
   `Только обновление=false`, `Обновить принудительно=true`,
   `Загрузить позиции В наличии=false`; из обновляемых данных отмечен только
   «Код товара/Артикул», значение которого осталось `test`;
   отсутствующие в файле товары — «Оставить без изменений».
4. Импорт `6ad68f8550712db41db1df54` завершился, обработано 1 из 1.
   Этот счётчик сам по себе не использовался как доказательство записи.
5. Прочитать исходный native ID и весь список через API, сравнить значения,
   проверить единственного владельца нового ключа и отсутствие новой карточки.
6. Проверить видимость: **Prom может опубликовать скрытый товар при таком импорте**.
   В тесте исходный скрытый статус восстановлен и проверен чтением.
7. Публикации обновлены кнопкой Console через штатную фоновую загрузку: чтение
   завершено, invalid=0. Прежний UUID получил `identity.state=valid` и новый ключ;
   общее число отсутствующих ключей уменьшилось 2 → 1. Все UUID публикаций,
   связи Catalog и исходящие разрешения Channel сохранились. На оставшуюся
   публикацию без ключа этот эксперимент не распространяется.

## Границы доказательства

Проверено назначение **отсутствующего** ключа одной существующей карточке через
родной XLSX. Исправление дублирующихся ключей, массовая загрузка, другие кабинеты
и режим `Только обновление=true` этим тестом не подтверждены. Для дублей сначала
проверяется одна конкретная карточка с сохранением native ID и всех прочих полей.
Результат нельзя переносить на самодельный CSV: прежний CSV-тест создавал дубль.
Инструкция не обещает сохранение скрытого статуса самим импортом.

Схема столбцов: [официальная документация Prom](https://support.prom.ua/hc/uk/articles/360004960817).

## Проверки реализации

- 57 backend unit/architecture tests; 53 PostgreSQL-проверки ядра, диагностики,
  связей и обновлений контента; 12 проверок полного Draft с локалями/галереей
  в одноразовых PostgreSQL/MinIO. Все прошли.
- 32 frontend-теста, ESLint, проверка типов и production build Console прошли.
- Браузер: реальный локальный API — сводка, missing-фильтр, URL/reload, отсутствие
  блокировки Draft/binding, SDK 5 connection form, отсутствие XML-диагностики Woo,
  подтверждённая инструкция и сквозное исправление после фонового чтения.
- Дополнительно изолированные браузерные fixtures проверили дубли между строками,
  копирование `00042`, переход к группе, неполную загрузку, empty/error/retry/loading.
  Fixtures не записывались в рабочую БД или Prom. SQL-коллизии отдельно проверены
  на настоящем PostgreSQL до фильтров и пагинации.
- Мобильная ширина 390 px и десктоп, без ошибок JavaScript. Browser plugin
  недоступен; использован штатный Playwright для локальной Console, нативный Safari
  через CUA для авторизованной формы Prom. Временные QA-сессии завершены.
