У строк нет повторяющихся непустых импортных ключей, а наборы адресатов по явно переданным идентификаторам не пересекаются. M06 использует две отдельные принадлежащие эксперименту карточки и не пересекается с другими строками. Порядок обработки строк не предполагается: после импорта нужно проверить все шесть существующих тестовых карточек, в том числе возможные изменения из-за недокументированного сопоставления.

M01 специально передаёт цену 13.37 вместо 1 UAH, количество 17 вместо 0 и наличие + вместо not_available. При обновлении только четырёх текстовых полей все три исходных значения должны сохраниться. Менять эти поля у ручного оригинала для такого контроля не требуется. M07 намеренно сохраняет пустой импортный ключ и передаёт пустой SKU для исключения сопоставления по артикулу; при обновлении исходный SKU TEST должен сохраниться. M02 и повторный M03 в файле 10 намеренно не содержат native ID существующей карточки: это отдельная проверка сопоставления по импортному ключу, хотя документация требует native ID для существующих товаров.

## Последовательность

1. **Этап 09, обычный импорт с разрешённым созданием.** Использовать публичный /products/import_url с полями name, description, name_ua, description_ua, force_update=false, only_available=false, mark_missing_product_as=none. Недокументированный is_import_v2 не передавать. Запрос и строки нужно оценивать независимо: для диагностических кейсов заранее неизвестно, будет обновление, отказ или дубль. Перед отправкой снова проверить снимки и отсутствие новых ключей.
2. **Зафиксировать результат до cleanup.** Прочитать тексты и все значимые нетекстовые поля. У M06 проверить обе исходные карточки. Новые товары искать по ключам и маркерам DNK CSV 09 Mxx, чтобы обнаружить дубли с пустым ключом. Затем скрыть созданные карточки, восстановить исходную видимость и наличие. Если M01 изменил цену, количество или наличие, сначала зафиксировать нарушение, затем восстановить эти значения и проверить их чтением.
3. **Этап 10, повторное обновление.** Включены M01/M02 и созданный M03. Импортные ключи сохранены, все четыре текста отличаются от этапа 09. Native ID M03 намеренно не подставлен: проверяется повторное адресование только по постоянному ключу. До запуска требуется фактически найти M03 по ключу и записать его выданный native ID. Если это не удалось или найдены дубли, этап 10 не запускать как полный файл. Успех: три прежних native ID, четыре новых текста у каждого, ноль созданных карточек. Идентичный повтор файла 10 может быть пропущен из-за force_update=false; критерий отсутствия дублей остаётся обязательным.
4. **Этап 11, отдельный режим Только обновление в кабинете.** Известный G01 и свежий G02 с ключом, не использованным в других файлах. Включить документированный ручной флажок, четыре текстовых поля и оставить отсутствующие товары без изменений. Периодическое обновление не настраивать. Успех: G01 реально обновлён, G02 отсутствует по native ID, ключу и маркеру. Отказ всего файла или нулевой счётчик created при необработанном G01 не доказывает защиту. Публичный is_import_v2 ранее не обеспечил этот режим и не заменяет проверку флажка кабинета.

## Что сохранять для каждого запуска

- SHA файла, параметры, снимки до отправки и точное время запуска.
- Import ID и одно намерение доставки до запроса. После принятия не дублировать запрос из-за задержки обработки.
- Фактические native/import ID, четыре текста и нетекстовые изменения каждой строки до восстановления.
- Проверку скрытого статуса созданных товаров после cleanup.

Оригинал 3239744864 участвует только в M04. Успешная привязка меняет его импортный ключ при сохранении native ID: это отдельный результат, который нельзя выдавать за полную неизменность исходного external_id=null. Другие товары и внутренний каталог не затрагиваются, безвозвратное удаление не требуется. Если состояние площадки изменилось после подготовки, обновить протокол и выпустить новую версию файла вместо молчаливого использования устаревших значений.

## Границы покрытия

В наборе проверяются обсуждённые способы сопоставления, создание, повторное обновление, защита цены/количества/наличия и ручной запрет создания. Нетекстовые поля дополнительно сравниваются со снимками. M01 содержит отличающиеся цену, количество и наличие; M07 отдельно проверяет сохранение SKU при пустом артикуле в файле. Галерея намеренно не меняется во входных данных, поэтому одна её неизменность не доказывает фильтрацию. Заведомо сломанные заголовки, отсутствующие единицы измерения и слишком длинные тексты не смешаны с основной матрицей. Отклонения в идентификаторах M02/M07 и повторного M03 описаны выше. Проверка исходного CSV-экспорта Prom без изменения его идентификаторов требует отдельного подлинного экспорта и не подменяется этим вручную сформированным файлом.
