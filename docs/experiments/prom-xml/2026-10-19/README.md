## Проверка запрета создания

### Предположение `only_update`

В тестах `07–09` проверялся предполагаемый недокументированный параметр
`only_update=true`. Он не был взят из публичного контракта. Рабочее обновление
в этих проверках не подтверждено:

- `07`: `total=2`, `imported=0`, `not_changed=1`, `created=0`, `updated=0`;
- `08`: `total=2`, `imported=0`, `updated=1`, но чтение известного товара
  до контрольного запуска `10` всё ещё возвращало прежние тексты;
- `09`: `total=1`, `imported=0`, `updated=1`, но исходный товар и его импортный
  дубль не получили тексты `01`.

При итоговом чтении все три операции возвращали `status=PARTIAL`.
Нулевой `created` здесь не доказывает гарантию «не создавать», а `updated=1`
не доказывает фактическую запись. Локальное ожидание завершено; успешное
завершение этих операций со стороны Prom не подтверждено.

Контроль `10` с тем же XML `05` **без `only_update`** дал `total=2`,
`imported=2`, `created=1`, `updated=1`. Перед запуском неизвестный импортный ID
отсутствовал. Известная карточка получила оба перевода `05`, а новый ID создал
товар `3239827664`, `external_id=dnk-xml-20261019-only-update`.
Следовательно, содержимое XML не препятствует созданию нового товара.

### Фактический параметр формы Prom

В публичном JavaScript кабинета переключатель «Только обновление» связан
с состоянием `isImportV2`; подготовка запроса передаёт `is_import_v2`.
Доступность зависит от флага `CMS_355_IMPORT_V2`. При выборе режима форма
отключает принудительное обновление. Кабинет использует собственные endpoints;
это не доказывает поддержку того же параметра публичным `/products/import_url`.

Для проверки подготовлен XML `06`: исходный native ID `3239744864` и неизвестный
`999999999999`. Отсутствие второго проверено по native ID и `external_id`.
Попытка `/products/import_file` (`11`) отклонена HTTP 400. После загрузки файла
владельцем на сервер проверено точное совпадение XML; запрос через
`/products/import_url` (`12`) также отклонён HTTP 400:

> В данный момент действует ограничение на запуск одновременных импортов.

Ни одна из попыток `11` и `12` с `is_import_v2` не получила import ID. Это отказ допуска
к запуску, а не результат обработки XML. Он не подтверждает и не опровергает
поддержку режима публичным API.

Запрос `12` (его повторение в `14` **не обеспечило запрет создания**):

```json
{
  "url": "https://bioline.com.ua/crm/06-native-update-v2.xml",
  "is_import_v2": true,
  "force_update": false,
  "only_available": false,
  "mark_missing_product_as": "none",
  "updated_fields": ["name", "description", "name_ua", "description_ua"]
}
```

Справка Prom также ограничивает ручной импорт: после 10 запусков за сутки
следующий доступен через 2 часа. До проверки `14` было принято 10 запусков;
последний — в `13:42` по Киеву (`10:42 UTC`). Это возможное объяснение отказов,
но точную причину по сообщению API определить нельзя. Внеплановая попытка `13`
около `15:24` снова отклонена тем же HTTP 400 без import ID. Однократная
запланированная попытка `14` после `15:42` была принята.

Проверка выполнена `19.10.2026` после `15:43` по Киеву. Исходное состояние
оригинала сохранено. Оба обращения к неизвестному `999999999999` — по native ID

Причину — игнорирование параметра либо другой требуемый контракт — один этот
эксперимент не устанавливает. Поведение переключателя в самом кабинете здесь

сопоставления групп; создание/удаление групп этим тестом отдельно не проверялось.

созданных экспериментом карточек скрыты. Повторное чтение подтвердило скрытый
статус всех шести товаров и сохранение значимых полей оригинала. Новых отправок
после принятого задания не выполнялось; однократный запуск завершён.

Для планируемой полной пакетной выгрузки остаются отдельными условиями:
корректные импортные идентификаторы, согласованная политика создания и сохранение
видимости/категории. Увеличение состава XML само по себе этих свойств не меняет.

Контрольная строка содержит все перечисленные поля. Исходный и размещённый CSV

По прямому запросу владельца около `20:54` по Киеву `19.10.2026` выполнен один
