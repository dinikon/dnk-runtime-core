# Проверка обновления CORE · 9 сентября 2026

Проверено локально на `http://localhost:8080`: Docker, PostgreSQL, Redis,
Nuxt SSR и Chromium с виртуальным WebAuthn-аутентификатором. Для браузерных
сценариев использовалась отдельная файловая почта и временные учётные записи.
Запросы Telegram в backend-тестах заменены тестовыми ответами; JWT подписываются
тестовым RSA-ключом. Настоящие письма и запросы входа к провайдерам не отправлялись.

| Проверка | Результат |
| --- | --- |
| Django checks, отсутствие новых миграций | Пройдено |
| CORE backend | 89 тестов пройдено; отдельный PostgreSQL-тест изоляции схем также пройден — 90 всего |
| Telegram | POST/CSRF, PKCE, подпись и claims JWT, одноразовый state, регистрация, MFA, привязка/отключение, ошибки провайдера |
| Passkey signup | Подтверждение email, resident credential и UV, резервные коды один раз, безопасный next, отмена и восстановление; отрицательные origin/challenge/UV |
| Браузер | 4 комплексных сценария: вход/passkey, регистрация, обычные формы и страницы безопасности |
| Формы | Без JavaScript; сохранение ввода и фокуса при загрузке Vue; Enter, пароль, полный OTP, выбранное POST-действие и защита от двойной отправки |
| Frontend | Shadcn Vue и Nuxt lint/typecheck/build; сборка компонентов Django, Docker и static files |
| Runtime frontend | Typecheck и production build пройдены |
| Runtime backend | Общий прогон с PostgreSQL: 145 пройдено, 1 отдельный тест конкурентности пропущен; его результат ниже |

Сравнены [утверждённые макеты](README.md) и снимки реализации: положение и
ширина Hero, основные действия, три блока возможностей, открытая форма входа,
постоянные подписи/ошибки, боковая навигация и строки настроек. На ширине 360,
390 и 1440 px проверены главная, вход, оба варианта регистрации, запрос кодов,
восстановление пароля и страницы безопасности. Контент аккаунта и список
провайдеров определяет сервер. Фокус с клавиатуры видим; Sheet закрывается
через Escape и возвращает фокус к кнопке меню. Кнопка закрытия имеет размер 44 px.
На семи публичных экранах не обнаружено ошибок JavaScript или горизонтального
переполнения. Проверка цветовых токенов: вторичный текст на светлой поверхности —
4,89:1, граница поля на белом — 3,03:1, фокус — 4,74:1.

Дополнительный запуск
`ScheduledJobsConcurrentClaimTests.test_concurrent_workers_do_not_claim_same_postgresql_job`
с `DNK_TEST_DATABASE_URL` обнаружил существующую ошибку runtime:
`sqlalchemy.exc.MissingGreenlet` при чтении `model.updated_at` в
`src/modules/shared/infrastructure/jobs/sqlalchemy_scheduled_job_repository.py:218`.
Код runtime и его зависимости этим обновлением не изменены. Это отдельная
неуспешная проверка, а не успешный результат регрессионного набора целиком.

Для повторного запуска браузерных сценариев и безопасной очистки тестовых
аккаунтов см. [инструкцию CORE frontend](../../frontends/apps/core/README.md).
Снимки сохраняются в `dnk-core-e2e-results` во временном каталоге ОС.
Рабочий Telegram Login проверяется отдельно после настройки Client ID/Secret
и публичного callback; реальная доставка email/Gateway также требует своих настроек.
После проверки обычная конфигурация Compose восстановлена; тестовых аккаунтов
не осталось. Главная и страницы входа доступны, `/api/me/` возвращает гостю 401.
