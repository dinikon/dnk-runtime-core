# Funnel

Funnel — отдельный контекст определения линейного процесса для `crm.lead` и
`crm.deal`. Не хранит карточки CRM, их коммерческие состояния или автоматизации.
Собственные таблицы: `funnels`, `funnel_stages`. Default-процессы обоих типов
создаёт tenant-миграция `0002_crm_sales_mvp`.

У воронки имя, неизменяемый тип, revision и 1–50 стадий. У стадии стабильный ID,
имя, семантический цвет и порядок. Перестановка/переименование сохраняют ID и
положение карточек. Удаление сохранённых стадий и воронок отсутствует в MVP.

POST/GET `/api/console/funnels` создают воронку и читают серверный список.
GET/PUT `/api/console/funnels/{id}` читают/заменяют определение. PUT требует
`expected_revision`. Новые стадии передаются с уникальным `client_key`,
сохранённые — со своим ID. Мутации доступны обычному аутентифицированному
пользователю текущего tenant и требуют CSRF.

`ResolveFunnelStageService` — публичный Application-контракт проверки назначения.
Он проверяет тип, принадлежность стадии, выбирает первую стадию при переносе и
возвращает собственный DTO. CRM вызывает его через свой порт/адаптер; внешняя
сборка использует ту же сессию UoW. Чтение для доменного решения удерживает shared
lock определения; изменение — exclusive lock до конца транзакции.

Console: `/funnels`, `/funnels/new`, `/funnels/:id`. Редактор отправляет полное
определение с версией, зафиксированной вместе с черновиком. Фоновое чтение не
заменяет эту версию. При конфликте пользователь видит актуальное определение и
свой черновик; явное принятие версии добавляет недостающие новые серверные стадии
для последующей сверки и сохранения. Доступны drag-and-drop и кнопки вверх/вниз.

Frontend-потребители используют только `modules/funnel/index.ts`. Определения
принадлежат TanStack Vue Query; черновик редактора — странице. Настроек, вкладок
и индикаторов триггеров/роботов нет.
