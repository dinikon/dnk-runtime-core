# Tenancy: локали tenant

Tenancy владеет списком локалей, разрешённых системой, и независимым набором
выбранных локалей каждого tenant. Начальный системный список: `uk` и `en`.
Его расширение требует изменения системного справочника в Domain; произвольный
код из HTTP-запроса добавить нельзя. Выбор хранится в таблице `tenant_locales`
своей tenant-схемы, поэтому отдельный столбец `tenant_id` не нужен.

## Поведение

- Tenant может выбрать любую системную локаль один раз. Повтор даёт `409`.
- Выбранный набор может быть пустым. Основная локаль пока не задаётся.
- Удаление убирает только выбор tenant. Тексты переводов и настройки каналов
  этим сценарием не изменяются; правила их использования будут уточнены перед
  реализацией Catalog и Channels.
- Добавление не создаёт переводы. Новые переводы в будущем должны проверять
  выбранный набор tenant. Fallback при отсутствии перевода ещё не определён.

## HTTP API

| Метод | Путь | Результат |
| --- | --- | --- |
| GET | `/api/console/tenants/locales/available` | Список `{code, name}` системных локалей |
| GET | `/api/console/tenants/locales` | Выбранные локали с `code`, `created_at`, `created_by` |
| POST | `/api/console/tenants/locales` | Выбор по `{"code":"uk"}`, ответ `201` с аудитом |
| DELETE | `/api/console/tenants/locales/{code}` | Удаление выбора, `204`; отсутствующий выбор — `404` |

Все маршруты требуют аутентификации. Tenant определяется из доверенного
`RequestContext`; POST и DELETE также требуют CSRF. Запись принимает только `code`.
Недоступный код и лишние поля дают `422`. Для просмотра и изменения выбранного
набора вызывается `AuthorizationService` с resource type `tenancy.locale` и
действиями `list`, `add`, `remove`; текущий default проекта — AllowAll.

## Слои и хранение

`domain/tenant_locale` содержит агрегат с естественным идентификатором-кодом,
VO, ошибки и системный справочник. `application/tenant_locale` содержит отдельные
сценарии добавления, удаления, чтения обоих списков и проверки выбора. Последний
(`IsTenantLocaleSelectedHandler`) служит Application-контрактом для будущих
потребителей Catalog и Channels. Write repository и read projection разделены.

SQL-адаптеры получают общую сессию UoW на tenant-bound соединении. Они не задают
`schema_translate_map`, не выполняют commit и не принимают tenant ID от клиента.
Таблицу создаёт tenant migration `0012_tenant_locales`. Существующие схемы нужно
обновить перед использованием API:

```sh
dnk-manage tenant-migrations upgrade --all
```
