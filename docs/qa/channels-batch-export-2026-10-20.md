# Проверка пакетного экспорта Prom — 20 октября 2026

Реализованы ядро пакетной операции, опциональная SDK capability, XML-плагин Prom,
ручной запуск, ежедневное durable расписание и Console. Каталог используется
только через существующий публичный фасад чтения. WooCommerce сохраняет свой
ручной сценарий; новая capability не требует добавлять ему пустую реализацию.
Поля и параметры Prom находятся в плагине; общий HTTP фасад ограничивает origin,
размер, JSON, redirects и время запроса.

## Контракт Prom

[Контрольный XML и результат](../experiments/prom-xml/2026-10-20/README.md):
у native ID `3240302692` прочитаны четыре новых текста RU/UK. Изменились только
названия и описания. Другие поля, остальные 26 карточек и набор native ID
сохранены. Исходный скрытый статус восстановлен после фактического завершения.
Прямой импорт обработался позже первых десяти минут; ранний SUCCESS/total=0 не
был признан подтверждением. Попытка import_url получила HTTP 400 без import ID
из-за ограничения параллельных импортов.

Проверку публичного endpoint приложения владелец отложил до публикации.
В локальном окружении публичный адрес не подставлялся фиктивным значением:
Console явно показывает необходимость настройки доставки и блокирует отправку.

## Автоматические проверки

- 77 unit/архитектурных проверок Channels: фабрики, правила слоёв, конкретные
  контракты, permission default/reset, XML, подписи, DST, SDK и регрессии чтения.
- 82 уникальных PostgreSQL-проверки выполнены поэтапно на одноразовых БД;
  файловые сценарии используют отдельный одноразовый MinIO. Основной набор
  регрессий — 78 проверок, новые дополнительные случаи проверены отдельно;
  окончательный пакетный набор из 15 проверок выполнен целиком после последних
  backend-изменений. Рабочая БД не использовалась для тестовых fixtures.
- Пакетный набор проверяет реальные controllers/CSRF/tenant UoW/Jobs/Catalog
  snapshots/Files/подписанный HTTP XML. Provider fixture действительно скачивает
  готовый файл из MinIO через endpoint модуля, разбирает XML и изменяет только
  тексты исходных карточек; новые ID не создаются.
- Проверены 51 позиция одним файлом, шесть конкурентных стартов, lost job,
  crash после фиксации submitting, потеря ответа POST, сверка вместо повторной
  отправки, пропуск конфликтов, stale binding/permission, сохранность непустой
  галереи и обнаружение изменения цены источником.
- Ежедневное due-событие проходит через production worker и lease, планирует
  следующий день, не дублируется, не сдвигается ручным запуском. Потеря deployment
  URL пропускает день с сохранением будущего события. Уже принятый импорт
  проверяется после выключения outbound.
- Поток MinIO закрывается даже при ошибке построения ответа до первого байта.
- 36 frontend-проверок Channels, включая DTO/mappers, tenant/session/page/filter
  cache keys, неизвестный результат, payload расписания и отображение времени
  в зоне policy вместо зоны браузера.
- Штатные `npm run lint:console`, `npm run typecheck:console`,
  `npm run build:console` выполняются из `frontends/` в build-окружении Node.

## Браузер

Chromium / Playwright, `http://localhost`, 1512×1050 и 390×844.
Специализированный Browser plugin отсутствовал; применён установленный Playwright.

На настоящем API проверены отображение карточки пакетного экспорта, готовность
доставки, выключенные defaults, разрешение отдельной связи, массовое выключение,
SQL-фильтр и URL/reload, сохранность исходной связи и прежний сценарий WooCommerce.
Глобальный outbound не включался. Проверочный флаг возвращён в false.

Для переходов, требующих публичного Prom URL, использованы явно контролируемые
ответы только batch endpoints: сохранение policy и pending, сохранность dirty
ввода при refetch, подтверждение/двойной клик с одним POST, прогресс до partial,
детальные причины, reload результата, reconciliation без повторной отправки,
empty, error/retry и loading skeleton. Эти UI fixtures не объявляются живой
проверкой Prom; backend того же сценария отдельно проверен через настоящий
HTTP/PostgreSQL/MinIO pipeline. Дополнительно в браузере с Europe/Kyiv подтверждено отображение UTC policy
на 12:00 без ошибочного сдвига к 15:00. Финальный успешный прогон не дал page errors;
на мобильной ширине нет горизонтального переполнения страницы.

## Локальная поставка и данные

Миграция 0033 подтверждена штатным tenant migrator. Образы API/Console собраны,
API, cron worker и event workers обновлены. SHA-256 исходников и миграций
в работающем API совпадает с checkout. До обновления сохранены закрытые
резервная копия и контрольный снимок.
После браузерной проверки все 325 публикаций, пять строк истории связей,
их ID/Catalog ID и глобальные флаги Channel совпали со снимком. Все новые
разрешения экспорта выключены. У одного представления revision увеличилась
на два из-за проверочного включения и выключения. Данные Catalog сценарием
экспорта не записывались. Временная QA-сессия отозвана; старый token получает 401.

## Архитектурная проверка diff

Проверены оба нормативных документа backend/frontend: Domain без SQL/HTTP;
create/restore и transitions у владельцев; публикации/каталог/связи не
переписываются миграцией; SQL в адаптерах; конкретные Command/Query/DTO/HTTP
контракты; пустые `__init__`; shared Jobs в одной транзакции с состоянием;
сеть между UoW; lease/sequence/recovery; опциональная capability вместо
условий по platform kind; Catalog/Files через публичные фасады.
Console разделяет api/DTO/mapper/model/query/mutation/Page/UI, использует общие
компоненты, scope/abort/invalidation, URL-фильтры, dirty/pending и доступные labels.
`git diff --check` проходит.

Ограничения: XML остаётся upsert при внешней гонке; вариации/скрытые карточки
исключены. Без сохранённого import ID неизвестный процесс автоматически не
освобождает слот даже после совпадения текстов — требуется ручной разбор.
URL истекает через семь дней, автоматическое удаление файлов истории отдельно
не реализовано. Публикации в локальном списке остаются наблюдаемым снимком
последней загрузки; исходящий run хранит собственный подтверждённый результат.
